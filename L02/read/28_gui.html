第 28 章 实时 GUI 与证据阅读

GUI 的作用是帮助你把多层状态放到同一时间线上理解。它是只读观察者，不替任务发速度，也不替评估器判定全图通过。学习时要特别区分“正在接收数据”“数据有效”“历史曾经有效”和“工作已确认”。

图为固定资料中的原机器人 GUI 示例，展示布局与字段，不代表本轮新运行点喷或新验收结果。

三层实现

ros_observer.py 订阅传感器与状态并保存有界预览；data.py 读取当前或历史运行目录、结果和事件，聚合可展示内容；server.py 提供 HTTP GET 接口；HTML/JavaScript 周期请求并更新画面。

Python 标准库 ThreadingHTTPServer 处理请求，threading 锁保护共享读取；浏览器 fetch 取 JSON，DOM 更新卡片和列表。传感器消息与磁盘日志来自不同周期，界面应同时保留来源时间与年龄，而不是强行把所有字段写成同一瞬间。

同一页面的四种状态

LIVE 表示关联正在运行的会话；HISTORICAL 表示保存结果；STALE 表示超过允许年龄；REJECTED 表示有数据但未通过算法准入。相机有画面可能只是最后一帧，不证明定位仍有效；点云有点不证明地形可通行。

当前服务通过 run 身份核对相机数据，避免新任务页面显示上一任务图片。启动时先占有 HTTP 端口，再启动观察子进程，减少重复启动造成孤儿观察者的风险。退出时只收尾自己创建的子进程。

def freshness(stamp, now, maximum=.5):
    if not isinstance(stamp, (int,float)) or not isinstance(now, (int,float)):
        return 'MISSING', None
    delta = now-stamp
    if not math.isfinite(delta): return 'MISSING', None
    return ('FUTURE' if delta < -.1 else 'FRESH' if delta <= maximum else 'STALE'), delta

函数区分无 stamp、时间不合法、过期与有效。新鲜度是观测条件，不是任务成功。界面字段应保留 source 和会话，避免历史快照被误当实时。

逐屏学习方法

总览先看任务/会话、目标序号、阶段和剩余预算。定位页看局部 odom、全局修正、GNSS 创新与拒绝。传感器页看频率、年龄、frame 和是否有效。决策页看 action、reason、evidence、thresholds 与 alternatives。工具页看请求、工作反馈、确认量、残余和 uncertainty。

把一条 WAIT 当作问题起点：定位不合格还是障碍短时等待？如果是定位，追到 GNSS_MAP_INNOVATION_OR_FRESHNESS 或匹配质量；如果是障碍，追到当前路径关系和阻塞持续时间；如果工具未工作，先看动作是否发出与准入条件。

文件与 HTTP 接口

当前服务绑定 127.0.0.1:8088。在同机可以读取：

curl -fsS http://127.0.0.1:8088/api/runs
curl -fsS http://127.0.0.1:8088/api/state

-f 让 HTTP 错误返回失败，-sS 隐藏进度但显示错误。端口未启动时连接失败是合理的；这些命令不会启动机器人。127.0.0.1 在 Windows 上指 Windows 本机，不会自动连接另一台 Linux；远程访问方案需要单独设计，当前教材不改变服务暴露范围。

频率和处理开销

传感器标称 10 Hz 与 GUI 每秒刷新几次不同。GUI 可以降采样展示，算法仍处理自己的频率；反之界面刷新快也不能补足传感器实际缺帧。观察 processing_wall_s、消息年龄和进程 CPU 时，要区分生产、传输、算法与显示开销。

历史运行只保存了有限证据，不一定包含全部图像或点云，不能凭结果 JSON 生成假实时传感器回放。静态教材的阅读页面也不会连接 ROS，它适合 Windows 学习，实时 GUI 适合 Linux 任务监视。

完整教学脚本 · 本章完整输出

代码只使用 Python 标准库；合成输入与历史记录在输出 kind 中区分。公共 ROOT、read、wrap、connected 等辅助函数在完整脚本中定义。

def lab28():
    """Freshness badge must be derived from timestamps, not file existence."""
    def status(now,stamp,valid):
        if stamp>now:return 'FUTURE_STAMP'
        if now-stamp>.3:return 'STALE'
        return 'VALID' if valid else 'REJECTED'
    rows=[status(10,9.9,True),status(10,9,True),status(10,9.9,False),status(10,11,True)]
    assert rows==['VALID','STALE','REJECTED','FUTURE_STAMP']
    return dict(kind='synthetic GUI semantics',badges=rows)
