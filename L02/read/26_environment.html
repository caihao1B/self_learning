第 26 章 环境搭建与资源迁移

阅读教材、运行教学例子、启动机器人是三个不同的环境层次。Windows 浏览器可以离线读全部正文与代码；Python 标准库可以跑三十个离线练习；真实仿真还需要 Ubuntu、ROS、Gazebo、编译产物和本地地图。源码仓库不是完整运行环境镜像。

当前学习基线的环境

作者机记录为 Ubuntu 24.04.5、x86_64、Python 3.12.3、ROS 2 Jazzy、Gazebo Harmonic。主要组件包括 robot_localization 3.8.3、RTAB 组件 0.23.13、BehaviorTree.CPP 4.10.0、Nav2 controller 1.3.13、Fields2Cover 2.1.1、OR-Tools vendor 9.9.1、METIS 5.1.0、nlohmann/json 3.11.3。完整 Debian 修订号保存在基线 manifest。

一个元包 ros-jazzy-rtabmap-ros 未安装，不代表所有 RTAB 组件缺失：当前 rtabmap、rtabmap-odom、rtabmap-slam 分别存在。检查依赖应读真正使用的组件，而不是只检测一个名字。

第一级 只读教材

在 GitHub 下载 ZIP，完整解压后打开根目录 index.html，再进入 L02 目录。不要只移动一个 HTML 文件，因为图片、代码与证据使用相对路径。没有网络时正文和本地素材可读，外部官方资料和 GitHub 链接需要联网。

Windows 若安装了 Python 3，可在仓库根目录打开 PowerShell：

py -3 --version
py -3 examples\l02\labs.py all

没有 py 启动器时，用实际安装的 python 命令，先通过 python --version 确认不是别的工具。教材不要求 Windows 安装完整 ROS，也不把 WSL 图形仿真视作已验收路径。

第二级 Linux 教学工具

以下安装命令供用户在自己的 Ubuntu 上执行，本轮教材检查不运行系统安装：

sudo apt update
sudo apt install python3 python3-venv build-essential libeigen3-dev nlohmann-json3-dev git ripgrep

apt 管理系统包，update 更新索引而非升级所有软件；install 安装指定包；sudo 仅提升该命令权限，密码只在本机终端输入，不写进脚本或仓库。build-essential 提供常用编译工具，Eigen3 提供第 14 章变换检查需要的矩阵头文件，nlohmann-json3-dev 提供 C++ JSON 头文件。

只运行 Python 离线练习不需要 pip。编译 C++ 示例见第 04 章。重建教材 HTML 才需要独立虚拟环境和 Markdown 库：

python3 -m venv .build_venv
.build_venv/bin/python -m pip install -r requirements-build.txt
.build_venv/bin/python tools/build_l02.py

这套环境只服务教材构建，与机器人 scene 环境分开。不要用 sudo pip 向系统 Python 混装科学计算包。

第三级 新机器 ROS 基础环境

先执行 cat /etc/os-release、uname -m、locale，确认 Ubuntu 24.04、架构与 UTF-8。Jazzy 官方安装说明明确支持 Noble。官方源码入口为 Jazzy 安装说明 和 软件源配置。软件源配置方式会随维护更新，历史硬编码 key 命令不应永远照搬。

以下是与该官方流程一致的软件源准备方式；先阅读下载来源，再安装：

sudo apt install software-properties-common curl
sudo add-apt-repository universe
robot_ros_source_version="$(curl -fsSL https://api.github.com/repos/ros-infrastructure/ros-apt-source/releases/latest | python3 -c 'import json,sys; print(json.load(sys.stdin)["tag_name"])')"
robot_ubuntu_codename="$(. /etc/os-release; printf '%s' "$VERSION_CODENAME")"
curl -fL -o /tmp/robot-ros2-apt-source.deb "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${robot_ros_source_version}/ros2-apt-source_${robot_ros_source_version}.${robot_ubuntu_codename}_all.deb"
sudo dpkg -i /tmp/robot-ros2-apt-source.deb
sudo apt update
sudo apt install ros-jazzy-desktop ros-dev-tools
source /opt/ros/jazzy/setup.bash

命令替换取得 release 标签和系统代号，双引号保护 URL 参数。每条下载命令失败就先处理错误，不继续安装旧的同名临时文件。这里安装的是当前可取得的 Jazzy 包；若要逐版本复现，必须核对基线修订号与可用快照源，不能把“同为 Jazzy”写成二进制完全相同。

基础通信测试使用两个终端，分别 source 后运行 ros2 run demo_nodes_cpp talker 和 ros2 run demo_nodes_py listener，看到对应消息后 Ctrl+C 停止各自进程。这只验证基础 C++/Python 通信，不验证机器人地图和任务。

第四级 机器人依赖与构建

在已配置 ROS 软件源的新机器，可先检查包候选：

apt-cache policy ros-jazzy-ros-gz ros-jazzy-navigation2 ros-jazzy-nav2-bringup
apt-cache policy ros-jazzy-robot-localization ros-jazzy-rtabmap-odom ros-jazzy-rtabmap-slam
apt-cache policy ros-jazzy-fields2cover ros-jazzy-ortools-vendor libmetis-dev

存在候选后按所需组件安装，并与 package.xml/CMakeLists 及 manifest 对照。ros-jazzy-ros-gz 使用 Jazzy 对应的 Gazebo 集成；不要把 Gazebo Classic 的旧插件包当 Harmonic 替代。历史 install_s01/s05/s06 脚本包含精确包版本和本机代理端口 10808，迁移机未必有该版本或代理，因此先读脚本而非盲跑。

sudo apt install ros-jazzy-ros-gz ros-jazzy-navigation2 ros-jazzy-nav2-bringup \
  ros-jazzy-robot-localization ros-jazzy-rtabmap-odom ros-jazzy-rtabmap-slam \
  ros-jazzy-behaviortree-cpp ros-jazzy-fields2cover ros-jazzy-ortools-vendor \
  libmetis-dev libompl-dev libeigen3-dev nlohmann-json3-dev

上面是核心依赖集合，不能替代全工程依赖解析。对独立迁移工作区执行 rosdep 可补充 package.xml 声明的系统依赖；手工 vendor、派生构建和本地资产仍需额外核查。

source /opt/ros/jazzy/setup.bash
cd /home/你的用户名/独立迁移目录/optimization_v2/ws
rosdep install --from-paths src --ignore-src -r -y --rosdistro jazzy
colcon build --symlink-install --parallel-workers 2
source install/local_setup.bash

这段目录是必须替换的迁移示例，不要在当前已绑定原工程执行全量重建。新机器尚未初始化 rosdep 时，在 install 命令之前运行一次 sudo rosdep init，再以普通用户运行 rosdep update；已有 sources list 时不重复初始化。--ignore-src 不安装工作区已经有源码的包；--parallel-workers 2 控制并行任务，不能保证每个编译器仅两个线程。colcon 完成也不自动重建 three_tasks 中所有确定性派生版本。

case $- in *u*) _v2_nounset=1; set +u ;; *) _v2_nounset=0 ;; esac

if [[ -f "$_V2_ROOT/ws/install/project_baseline/share/project_baseline/local_setup.bash" ]]; then
  source "$_V2_ROOT/ws/install/local_setup.bash" || return $?
fi
export ROS_DOMAIN_ID=119 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST ROS_STATIC_PEERS=''
export GZ_PARTITION=robot_optimization_v2
export DINO_PROJECT_ROOT="$(dirname "$_V2_ROOT")"

unset _V2_ROOT _v2_nounset

环境脚本重置 overlay 并加载 Jazzy，运行它不安装地图、虚拟环境或编译库。新机器需要分别准备这几层；当前机 source 后的 check 也只验证回执绑定范围。

Python 科学计算环境

当前 scene 环境的重要版本包括 NumPy 1.26.4、SciPy 1.11.4、Shapely 2.1.2、PyYAML 6.0.1、Pillow 10.2.0、imageio-ffmpeg 0.8.1。ROS Python 包来自系统 Jazzy，场景脚本还用到图像、几何、视频等依赖。不要将这些部分列表当完整锁文件。

新迁移目录中可用 python3 -m venv --system-site-packages optimization_v2/venvs/scene 访问系统 ROS Python，再按固定资源与依赖清单安装项目需要的包。用该解释器执行 -m pip，并检查 sys.executable、模块版本及导入位置。直接复制 venv 往往含绝对路径，不是可靠跨机器迁移方式。

教学验证与故障

python3 examples/l02/labs.py 26 核对学习包内固定快照哈希，不检查没有打包的大数据库。安装失败先区分软件源、包版本、代理、系统 ABI、Python 解释器与资源缺失；不能用扩大权限或 sudo pip 一次性掩盖。

本章练习核心代码与实际输出

完整教学脚本 · 本章完整输出

代码只使用 Python 标准库；合成输入与历史记录在输出 kind 中区分。公共 ROOT、read、wrap、connected 等辅助函数在完整脚本中定义。

def lab26():
    """Check shipped immutable material without installing dependencies."""
    counts=[]
    for name in ['baseline/manifest.json','baseline/l02_manifest.json']:
        m=read(name);checked=0
        for e in m['entries']:
            if not e.get('local'):continue
            data=(ROOT/e['local']).read_bytes()
            assert hashlib.sha256(data).hexdigest()==e['sha256'],e['path']
            checked+=1
        counts.append(dict(manifest=name,checked=checked,commit=m['commit']))
    return dict(kind='actual snapshot verification',manifests=counts)
