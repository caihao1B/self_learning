第 14 章 全局定位与 GNSS 偏移监督

局部 odom 连续不等于全局地图位置正确。当前系统通过区域观测云匹配提出地图位姿，再用 GNSS、质量、时效性与跳变检查决定是否接受。定位失败会直接影响停车和作业准入，因此它也是完整 A1 未通过的重要观察点。

区域配准的输入与输出

输入是当前点云、同一时刻附近的局部里程计、固定参考云、初始提示和 GNSS。输出不仅是 pose，还有 valid、reason、采集时间、配准残差、重叠、候选分歧和 GNSS 创新。

首次配准使用粗初值并尝试多个小航向扰动，随后由上一全局位姿和局部里程计增量预测新的初值。多个候选彼此不一致时拒绝“模糊初始匹配”。跟踪阶段若配准相对预测的修正过大，也拒绝直接应用。

留出几何验证把部分观测用于独立检验配准，减少只在优化用样本上自我满意。它不是与外部世界完全独立的真值验证，仍可能受地图重复结构和共同误差影响，因此还需要 GNSS 与质量监督。

GNSS 如何变成地图中的点

经纬高先通过大地坐标转换到局部 ENU，即 East、North、Up。局部 datum 和 site_origin 决定地图基准。然后比较天线位置与预测天线位置：p_ant=p_base+R(yaw)*lever。杆臂 lever 在车体坐标中，必须随航向旋转。

当前代码选择接近点云时间的 fix，并要求相应状态与时间窗口。若车移动时使用不同时刻 GNSS，差值包含真实运动，就可能被当成定位偏差。

创新和 NIS

创新 r 是 GNSS 观测减预测。合成协方差 S 包含 GNSS 与地图位姿不确定性。归一化创新平方 NIS=rᵀS⁻¹r 衡量误差相对不确定性有多大。实际区域代码同时要求平面残差不超过 0.15 m、NIS 不超过 9.21，并检查协方差正定性。9.21 对应二维卡方约 99% 分位的常用统计门限；实际非高斯与相关误差会限制这种解释。

只用 NIS 会有一个风险：把协方差随意调大就能降低 NIS。绝对残差门限提供额外约束，但同样需要真实校准。教材不通过改门限让旧失败消失。

修正抖动与滤波

当前区域前端对 map→odom 修正使用短窗口中位统计；R10 C++ 还提供指数修正滤波，alpha=1−exp(−dt/tau)，平移插值，旋转用四元数 slerp。dt 小时用 -expm1(-dt/tau) 改善数值精度。

滤波只作用于全局修正，局部 odom 保留高频运动。更重要的是原始创新、跳变、时效性和计划约束先检查，再平滑。若先滤波再检查，错误的大跳变可能被拆成许多小步而逐渐混进系统。

correction_filter.hpp 第 1 至 22 行

离线带行号源码 · 固定 Git 提交

#pragma once
#include <Eigen/Geometry>
#include <cmath>
#include <stdexcept>

namespace r10 {
// Filter only the map->odom correction. Local odometry retains its full rate.
// Caller must check RAW innovation, jumps, freshness and plan holds first.
inline Eigen::Isometry3d smoothCorrection(const Eigen::Isometry3d &previous,
                                         const Eigen::Isometry3d &observed,
                                         double dt, double tau) {
  if (!previous.matrix().allFinite() || !observed.matrix().allFinite() ||
      !std::isfinite(dt) || !std::isfinite(tau) || tau <= 0.)
    throw std::invalid_argument("invalid correction filter input");
  if (dt <= 0.) return previous;
  const double alpha = -std::expm1(-dt / tau);
  Eigen::Isometry3d result = Eigen::Isometry3d::Identity();
  result.translation() = previous.translation() + alpha * (observed.translation() - previous.translation());
  result.linear() = Eigen::Quaterniond(previous.linear()).slerp(alpha, Eigen::Quaterniond(observed.linear())).normalized().toRotationMatrix();
  return result;
}
}

Eigen::Isometry3d 同时保存旋转和平移，allFinite 拒绝坏矩阵。alpha 用 expm1 提高小 dt 数值稳定性，旋转用四元数 slerp 再归一。调用者必须在此之前检查原始异常。

在 Linux 编译真实 C++ 判据

读完 Python 的区域配准，再看 C++ 的小函数，有助于理解语言分工：Python 负责数据组织与状态流程，Eigen 在 C++ 中提供固定尺寸变换运算。const ... &previous 用常量引用传入已有变换，避免不必要的复制，也禁止函数通过此参数改写输入；返回的 result 是新的变换。inline 允许这个头文件定义被多个编译单元包含，并不保证编译器一定进行指令内联。

停车重验证为什么分阶段

定位失效时，先停工具、取消导航、确认车体静止，再收集足够新鲜且一致的候选。prepare 阶段保存将要接受的证据，commit 阶段确认关联版本与状态仍满足条件后应用。这样避免检查通过与真正恢复之间状态已改变。

恢复不能无限循环。原完整 A1 的结果因 LOCALIZATION_REVALIDATION_BOUND 停止，说明有界恢复条件被触发；不能仅凭这个名字宣布根因已完全确定。可能涉及观测几何、GNSS 创新、时间、初值或全局抖动，应结合当时的原始拒绝证据区分。

一个数值例子

车体在 (10,20) m，航向 90°，天线前置 0.5 m，则天线预测是 (10,20.5)。GNSS 观测 (10.03,20.52)，实际创新只有 (0.03,0.02)；忽略杆臂会看到约 0.52 m 的错误偏差。执行 python3 examples/l02/labs.py 14 可核对 NIS。

def lab14():
    """Antenna lever arm and a diagonal two-dimensional innovation test."""
    body=(10.,20.); lever=(.5,0.); yaw=math.pi/2
    antenna=(body[0]+math.cos(yaw)*lever[0],body[1]+math.sin(yaw)*lever[0])
    fix=(10.03,20.52); residual=(fix[0]-antenna[0],fix[1]-antenna[1])
    variance=.02**2+.05**2; nis=sum(x*x/variance for x in residual)
    assert nis<9.21
    return dict(kind='synthetic pose with production-style gate',antenna_m=antenna,
                residual_m=residual,NIS=nis,threshold_2d=9.21,
                omitted_arm_residual_m=math.dist(fix,body))

手工观察与排查顺序

先在 GUI 看 raw pose、filtered correction、GNSS innovation、NIS、accepted/rejected reason 与数据年龄，再对照任务精停窗口。只看车体动画可能看不到厘米级全局抖动。若图像稳定而定位仍 WAIT，需要查看是哪一个准入条件未满足。

检查顺序是坐标与杆臂、采集时间、fix 状态与协方差、匹配候选质量、原始修正跳变、滤波输出、恢复状态机。不要第一步就增加允许创新或放宽作业位置误差。

自测

问：同一个 GNSS 已强制拉动全局位置，再用它验证该位置，是否独立？答：独立性降低，应记录数据来源和相关性，不能将同一信息重复当证据。

问：静止单天线 GNSS 能否直接修正 yaw？答：一个位置点不能充分约束航向，需要运动基线、双天线或其他方向信息。

练习：分别改变教学例子的杆臂、协方差和采集时差，解释哪一个改变几何、哪一个改变统计权重、哪一个产生运动相关误差。
