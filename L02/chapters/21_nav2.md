# 第 21 章 Nav2 动作与规划器

项目中有到点、巡检、覆盖三类导航用途，主要使用的 ROS 动作是 NavigateToPose 与 FollowPath 两种。不要因为阶段标题写“三类导航动作”，就自行补出第三个已经部署的接口。ComputePathToPose 是规划接口，NavigateThroughPoses 是可选上游能力，但不能据此宣称当前任务已使用。

## NavigateToPose 的责任

调用者给目标位姿，导航行为树组织规划与跟踪。当前到点链路使用 Smac 规划及相应末端适配，路径由当前地图、起点、目标和配置决定。周期重规划可以更新连接，却可能使短末端路径在栅格上跳动，因此需要仔细处理精确目标与格心的差异。

导航成功由 goal checker 判定，通常有位置和航向容差。喷洒还要求工具位置、静止样本窗口和反馈条件，所以 NavigateToPose SUCCEEDED 后不能立刻增加作业完成量。

## FollowPath 的责任

调用者提供路径，由 controller server 跟踪。它适合保持覆盖条带或巡检路线的几何意图。FollowPath 本身不自动替你完成全局重新规划；任务监督需要决定何时取消、等待、构造替代路径或保存残余。

路径包含坐标系、时间戳、位置与方向。只给很多 xy 点而不正确处理 yaw、换挡和连续性，阿克曼车可能收到不可执行路径。修改路径后还要检查它是否改变工作段与工具状态。

## 规划器 控制器 代价图

规划器计算空间路线，控制器周期性给速度，代价图提供可通行与风险表示。global_costmap 与 local_costmap 可能使用不同窗口和分辨率。地图服务、规划器、控制器和 BT navigator 还受生命周期管理。

SmacPlanner2D 在二维栅格上搜索，中心点或格心离散可能影响末端精度。阿克曼受非完整约束的连接还使用专门几何后端，不应让任意二维折线直接交给阿克曼跟踪。选用成熟库仍需要把车体合同完整传入。

## 动作调用的真实顺序

等待服务器 ready，发送 goal，检查 accepted，保存 goal handle，取得 result Future，持续 spin 并检查 BT，必要时申请 cancel，确认结果和物理停止，再提交下一段。一个旧 Future 未收尾时创建新控制所有者，容易出现路径竞争或取消误杀新目标。

## 代价图未知格与足迹

未知格、已观测障碍和先验自由格应有明确优先级。实时危险应立即生效，静态先验只能在其授权范围内补充已知信息，不能删除刚观察到的障碍。不同阶段参数也可能不同，读当前 R09/R10 导出配置，而不是照搬早期 S13 的小车半径与速度。

足迹、footprint_padding 和分辨率共同影响碰撞检查。中心线通过一格间隙，不代表整个车体通过。离线连接需要预留与在线栅格一致的余量，否则在线控制拒绝路径是合理行为。

## 常见故障与自测

action server 缺失：查生命周期、namespace、domain；goal accepted 后不动：查门控与 controller 日志；规划成功但跟踪失败：查路径曲率、足迹、实时风险和目标方向；频繁取消：看上层 BT 原因与数据年龄；末端反复重规划：看精确目标与栅格中心差异。

问：什么时候选择 NavigateToPose？答：目标位姿重要、连接允许由在线规划决定时。什么时候选择 FollowPath？答：已有可执行路径，其几何与任务语义需要保留时。

练习：为点喷接近、局部精停、覆盖条带、道路巡检各选一个动作，并写出取消后需要保留的任务信息。一个任务可以在不同阶段使用不同动作。
