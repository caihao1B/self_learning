# R09 割草任务技术

状态以有效阶段回执为准。Dino 保留 R02–R04 的真实简化尺寸、前阿克曼关节、最小后轴转弯半径约 3 米和完整车体碰撞轮廓。原 R03 的 B1–B3 路径与工作区分母保留，不通过缩小车体或临时扩大作业区来容纳转弯。

离线条带由 Fields2Cover 生成，地头使用通过完整足迹检查的 OMPL Reeds–Shepp/Dubins 段。每个方向或曲率切换段先停车。Nav2 RPP 允许倒车、禁止原地转向，底盘出口同时限制速度、方向及曲率；倒车最高 0.25 m/s，前进作业指令最高 0.35 m/s（实测作业上限仍为 0.4 m/s），低于 R04 的物理资格候选上界。

每个 COVERAGE 段先提交 START_WORK，等待真实模拟电机反馈确认工作，再发送 FollowPath。转场、地头和倒车段必须确认工具已经停止。遇到感知、定位或 BT 取消，导航和工具同时申请取消，分别确认车体和电机停止，保留账本。实际抵达段末是导航完成，不等于割草覆盖率达标。

工具仍是抽象动作，无机械臂和真实切割模型。账本只接纳新鲜、同时间定位、有效工作段、合格速度和真实电机反馈。每帧有效工具足迹按姿态误差预算侵蚀后，与请求条带区域求交、固定精度并集，重走不重复计入。工具宽度 1.6 米，长度 0.7 米；姿态侵蚀半径按当前工具尺寸计算。独立真值评估只用于验证账本没有虚增，不进入控制。

默认组件案例选择 B1 原序前五段：两条作业条带和中间三个关闭工具的倒车地头段；它不能代替完整 B1。全 B1 与三任务分别验收由 R10 独立执行。原 95% 的工具完成判据不改；段走完但面积不足时，工具动作及残余如实保持 PARTIAL/CANCELLED，任务报告分别列出段完成量和反馈面积。

R09 对 Dino 单独生成有效传感器版本：主激光采用 R08 实测配置的 128×2048、10 Hz，标定仍来自 Dino 自身的 R05 外参和误差模型；四个近地通道按 Dino 实际轮廓布置。它不能直接继承 Jackal 的定位通过结果，必须在本阶段真实复验。每次运行独立配置 DDS 共享内存缓冲，主点云的真实宽高写入地图预处理日志。

本阶段割草节点使用当前方向的实测地形保护与 Nav2 碰撞检查；没有启用巡迹专用的前车跟随和横穿预测通道。绕行搜索只提供受阻诊断：若找到替代路径但需要重新编排条带，保留残余并报告该原因，不直接把自由导航路径替换成割草完成量。

### 割草车的启动定位稳定性

首次真实启动时，静止 Dino 的区域匹配在两个相近解之间波动，短窗口准入后触发了 0.15 米全局跳变保护。该失败保留，未确认任何作业量。

R09 使用独立的地图匹配入口，对 `map→odom` 校正采用最长 4.2 秒、25 个样本的中位数滤波；启动对实际中位数校正输出再次检查，还需至少 18 个样本、3.5 秒跨度、平移离散度不超过 0.06 米、航向离散度不超过 0.01 弧度，并连续满足 3 秒。滤波对象是坐标校正，不是滞后的车辆位置，输出仍投影到当前实测里程计时刻。原跳变、GNSS 创新与停车条件不放宽，也不自动确认已触发的诊断保持。已封存 R08 使用自己的配置与源码。

Dino 宽车体的主雷达自车边缘噪声曾产生假障碍。R09 地形分支使用与该车原传感器误差量级匹配的 0.05 米自车过滤余量；不因此清空周围未知格，也不修改真实碰撞体或保护范围。传感器原始记录用于确认误检来源。

### 后轴原点与车身中心不能混用

Dino 车身轮廓相对后轴为 x∈[-0.571,2.209]，几何中心在 x=0.819 米。几何库默认绕多边形中心旋转，会使车身边界与 Nav2/物理模型错位。R09 明确按后轴原点 `(0,0)` 旋转再平移，同时用于实时当前车身未知格处理和离线整车边界检查。只处理当前真实车身内的未知格，0.10 米安全余量范围仍要求观测，不清除实测危险。

### 面积账本的几何退化处理

工具足迹与条带边界相切时，几何交集可能包含面、线和点。R09 在网格精度并集前后只提取面；边界线与点贡献零面积。几何库拒绝某帧时记录 `GEOMETRY_REJECTED` 并保留已确认量，不以异常帧增加面积，也不让账本进程因该异常退出。此前真实运行触发的混合维度异常、停止未确认结果保留为失败。

Dino 的近地通道改为实际 128×128 采样，分别位于车体前、后、左右边界外 5 毫米、高 0.23 米处。前 64 线版本在侧前安全余量内出现间歇观测空洞，RPP 反复拒绝前进并最终受控上报。新版本通过实际增加观测密度解决，保留未知格不可执行的规则；传感器配置、场景与任务绑定随之重新生成。

### 保留车尾真实地面观测与端点曲率控制

Dino 的 0.05 米自车过滤余量会覆盖少量真实地面，车尾边界格因此可能变成未知。独立 C++ 地形节点保留该余量环带内高度不超过 0.08 米的真实回波；实体车身内部仍过滤自车点。低矮台阶和负障碍点一并保留，再由原地形统计判断风险，不生成空地或绕过未知限制。8 项 C++ 检查覆盖实体车身、噪声边缘、真实地面、4 厘米低障碍及负障碍。

原短预瞄在端点附近因距离很小而要求过大曲率，阿克曼出口正确裁剪后无法满足航向到达条件。R09 使用 Nav2 Jazzy 已有的固定 0.8 米曲率预瞄及终点后切线插值，以避免端点曲率奇异。插值只用于计算控制曲率，导航目标和原到达门限保持不变，仍不能原地旋转。该配置经本机已安装头文件和 [Nav2 Jazzy 官方说明](https://api.nav2.org/nav2-jazzy/html/md_nav2_regulated_pure_pursuit_controller_README.html) 核实；实际效果以真实五段测试为准。

### 工具反馈与仿真时钟的消息顺序

ROS 的时钟与电机反馈是两个话题，接收顺序不保证等于采集顺序。R09 独立工具服务暂存尚未到达时钟纪元的反馈（最多 30 条），时钟到达后按原始时间戳接纳；不重写反馈时间，也不重置实际接收墙钟。旧反馈、断流、错误会话与错误工具版本继续按原门限拒绝。发生反馈新鲜度故障时记录当前时钟、传感器时间、实际接收龄期和缓冲数，便于区分话题排序与真正断流。该改动不替换已验收 R07/R08 的二进制。

真实复验的故障记录进一步显示：一次反馈龄期达到 0.106 秒（原门限 0.1 秒），实际接收墙钟龄期 0.218 秒，缓冲为空。因此仅修正消息排序不足。R09 将工具桥接从近地大点云桥接进程分离，并用独立模拟插件把电机原始采样设为 50 Hz，保留 0.02 秒传感器延迟与所有反馈有效期、停止确认门限。工具实际关节速度仍由物理引擎产生。工作速度指令调为 0.35 m/s，与原 0.4 m/s 实测速度门限留出跟踪误差余量，避免指令恰好贴门限造成反复启停。

### 遮挡下的启动样本收集

持续障碍案例显示，合格匹配频率会低于 5 Hz；把“18 个合格样本”硬塞进 4.2 秒窗口会让车辆永久等在启动阶段。R09 将**准入证据窗口**独立设为最多 7 秒，地图改正中位数窗口仍为 4.2 秒。仍要求 18 个合格样本、至少 3.5 秒跨度、原 0.06 米/0.01 弧度稳定性及 3 秒持续稳定；相邻合格观测最大间隔必须不超过原 0.6 秒新鲜度界限。短暂拒绝的匹配不会作为有效定位发布，也不重置尚未超龄的稳定证据；超过 0.6 秒则重新等待。新增检查覆盖低频合格样本和超龄缺测，原 GNSS/几何/跳变门限不变。

### 持续障碍案例的触发时机与限制

初次装配就放在车前的大障碍遮挡了区域地图特征，多次启动未满足地图/GNSS 一致性及稳定样本要求；车辆停在启动阶段并上报人工。这些失败结果保留，不能算作已经测试了路径绕行，也不能声称任意遮挡下均能重定位。

通行故障用例改为**正常定位完成、测得行驶至少 0.30 米后**，由模拟边界向原定位置放置同样的 0.6×4.5×1.2 米实体障碍，随后保持不动。测试控制器只操作障碍物装配，不修改机器人位姿、地图或在线风险栅格。车端仍只能用真实模拟传感器发现障碍，规划与工具节点读不到放置坐标。验收要求物理创建成功回执、真实运动、规划查询、停止确认及残余；障碍未实际创建时测试必须失败。启动遮挡的定位限制与行驶受阻的验收范围分别报告。
