`spray_20261115_050057_428551` 完成 26/56 点后，在约 3.67 cm 的局部精停中触发 `MOTION_WITHOUT_OBSERVED_PROGRESS`。原 BT 要求 10 秒内累计至少 10 cm 等效里程进展，短动作本身没有足够位移满足该条件。已执行 26 点的逐点计量、独立物理误差和幂等反馈符合原要求，整簇仍是 PARTIAL。该次定位 RMSE 约 0.04377 m；录像时间线完整且图像新鲜。

本次增加独立的点喷 BT 程序，不修改巡检和割草原生监督器。只有完成停车、几何和当前代价图检查后派发的局部精停动作，才携带 `VALIDATED_LOCAL_DOCKING` 运动范围及已验证的目标位移 `d`。该范围要求 `0.008 < d ≤ 0.15 m`，进展增量为：

```text
min(原 0.10 m, max(0.005 m, 0.25 × d))
```

10 秒停滞超时不变，单次局部动作最多 45 秒、最多两次物理修正不变。普通导航仍要求原 0.10 m 进展。缺失、超界、非有限的请求不能使用精停尺度。原全局导航、1.8 秒静止观测、位置和散布、实测停车、碰撞与工具反馈门限全部保留。

核心代码：C++ `r10_backend/precision_progress.hpp` 给出有界进展尺度；`precision_supervisor_r10.py` 从原策略确定性派生单独二进制；`mission_spray_r10.py` 只在合格局部路径发出时标记范围；`control_spray_r10.py` 复核范围、位移及任务消息新鲜度，再传入 BT。GUI 可直接查看 `effective_progress_delta_m`、运动范围和剩余预算。

```bash
cd /home/ceihao/robot_project
bash optimization_v2/three_tasks/gui.sh
# 浏览器打开 http://127.0.0.1:8088

# 独立 BT 检查，不启动 Gazebo
bash optimization_v2/three_tasks/advance.sh R10 test precision_progress

# 下一终端：一次只运行一个任务
bash optimization_v2/three_tasks/advance.sh R12 record spray
```

界面支持当前/历史任务切换、原始证据、反馈账本、传感器采样和相机画面。14 项有界读取/状态隔离测试及真实浏览器交互检查单独记录为 GUI 证据。GUI 正常运行不会升级 R10–R12 的任务验收。
